# Шифрование сообщений и цифровая подпись

Программа показывает, как передать сообщение в зашифрованном виде и проверить, дошло ли оно без изменений. На одном компьютере открываются два окна. В окне **«Отправитель»** вы пишете текст, шифруете его, подписываете и отправляете. В окне **«Получатель»** вы проверяете подпись и восстанавливаете исходный текст.

## 1. Скачайте и запустите программу

Если у вас ещё нет файлов, откройте [репозиторий на GitHub](https://github.com/1dober1/crypto-practice). Нажмите **Code → Download ZIP**, распакуйте архив и откройте распакованную папку в VS Code через **Файл → Открыть папку**. Внутри неё должна быть папка `pract6`.

Нужен Python 3.9 или новее с Tkinter. Для проверки Tkinter в терминале выполните `python3 -m tkinter` на macOS или Linux либо `py -m tkinter` в Windows. Если откроется тестовое окно, закройте его и запускайте программу.

Когда проект открыт в VS Code, выберите в верхнем меню **Терминал → Создать терминал**. Терминал откроется внизу. Команды вводите по одной, нажимая Enter после каждой.

Если в терминале вы находитесь в папке проекта и видите подпапку `pract6`, выполните на macOS или Linux:

```sh
cd pract6
python3 app.py
```

В Windows выполните:

```powershell
cd pract6
py app.py
```

Если терминал уже открыт в `pract6`, выполните только вторую команду. Признак правильной папки: в ней лежит `app.py`. После запуска должны появиться два окна. Если видите только одно, проверьте, не оказалось ли второе за ним.

## 2. Что означают ключи и подпись

**Шифрование** превращает читаемый текст в шифротекст. **Расшифровка** восстанавливает исходный текст. **Цифровая подпись** позволяет получателю проверить, что пакет подписан ключом отправителя и дошёл без изменений. В этой программе подпись ставится на шифротекст. Байты шифротекста и подписи в интерфейсе показаны цифрами и буквами от `a` до `f`. Это шестнадцатеричная запись байтов, сокращённо **hex**.

Каждый алгоритм создаёт пару ключей. **Открытый ключ** передают другому участнику. **Закрытый ключ** остаётся у владельца.

| Что нужно сделать | Какой ключ используется |
| --- | --- |
| Зашифровать сообщение | Открытый ключ **получателя** |
| Расшифровать сообщение | Закрытый ключ **получателя** |
| Подписать шифротекст | Закрытый ключ **отправителя** |
| Проверить подпись | Открытый ключ **отправителя** |

За шифрование отвечает алгоритм **Голдвассер-Микали (GM)**, за подпись отвечает **HORS**. На первую отправку достаточно создать одну пару GM у получателя и одну пару HORS у отправителя.

## 3. Отправьте первое сообщение

### Шаг 1. Подготовьте генератор в обоих окнах

1. В окне **«Отправитель»** откройте вкладку **«Ключи»**.
2. Поводите курсором внутри голубого поля. Счётчик над ним вырастет от `0/96` до надписи **«Генератор готов»**. Нажимать мышью не нужно.
3. Перейдите в окно **«Получатель»** и сделайте то же самое. У каждого окна свой генератор.

Движения мыши дают генератору начальные данные, из которых он получает числа для создания ключей и шифрования.

### Шаг 2. Получатель передаёт ключ шифрования

1. В окне **«Получатель»** на вкладке **«Ключи»** нажмите **«Создать ключ шифрования»**.
2. Дождитесь записи **«Готова пара GM»** в журнале. Поиск больших простых чисел занимает некоторое время.
3. В этом же окне нажмите **«Передать открытые ключи»**. У отправителя в строке **«Полученные ключи»** появится **«шифрование»**.

### Шаг 3. Отправитель передаёт ключ проверки подписи

1. В окне **«Отправитель»** на вкладке **«Ключи»** нажмите **«Создать ключ подписи»**.
2. Дождитесь записи **«Готов ключ HORS на одну подпись»**.
3. В этом же окне нажмите **«Передать открытые ключи»**. У получателя в строке **«Полученные ключи»** появится **«подпись»**.

Программа сама передаёт ключи между окнами. Копировать числа из поля **«Открытые параметры»** вручную не требуется. Кнопка **«Показать закрытые параметры»** пригодится, если на защите нужно показать секретные множители `p` и `q`.

### Шаг 4. Отправитель готовит и передаёт сообщение

1. В окне **«Отправитель»** откройте вкладку **«Отправка»**.
2. В поле **«Сообщение»** введите `Привет!`. Для первого раза используйте короткое сообщение. Программа принимает до 128 байт в кодировке UTF-8.
3. Нажмите **«Зашифровать»** и дождитесь заполнения поля **«Шифротекст, hex»**.
4. Нажмите **«Подписать»**. Заполнится поле **«Подпись, hex»**.
5. Нажмите **«Передать»**. В окне получателя откроется вкладка **«Приём»** с копией шифротекста и подписи.

### Шаг 5. Получатель читает сообщение

1. На вкладке **«Приём»** нажмите **«Проверить подпись»**. В журнале появится **«Подпись действительна.»**
2. Нажмите **«Расшифровать»**. В поле **«Расшифрованное сообщение»** появится `Привет!`. Кнопка расшифровки перед показом текста сама проверяет подпись ещё раз.

## 4. Покажите, что подмена обнаруживается

1. В окне **«Получатель»** нажмите **«Изменить один блок»**. Эта кнопка меняет копию шифротекста у получателя.
2. Нажмите **«Проверить подпись»**. Журнал сообщит, что подпись недействительна. При нажатии **«Расшифровать»** программа остановит операцию.
3. Вернитесь в окно **«Отправитель»** и снова нажмите **«Передать»**. Получатель получит исходную копию. Теперь проверка и расшифровка снова пройдут.

Для **нового сообщения** в окне отправителя создайте новый ключ подписи и передайте его открытый ключ. Затем заново введите текст, зашифруйте, подпишите и передайте его. Пара HORS рассчитана на одну подпись. Уже созданную подпись можно проверять и пересылать многократно. Пару GM получателя можно использовать для нескольких сообщений.

## 5. Зачем нужна вкладка «Простые числа»

Простое число делится без остатка только на 1 и на себя. Например, 7 простое, а 9 составное, потому что делится на 3. При создании ключа GM программа сама ищет два больших простых. Они нужны для шифрования и расшифровки. HORS использует хеши, поэтому для подписи простые числа не нужны.

Вкладка **«Простые числа»** позволяет отдельно показать генерацию, проверку и поиск чисел по примеру `L_PROST.EXE`. Здесь для проверки используются тесты Миллера-Рабина и Соловея-Штрассена. Она доступна в обоих окнах, но для демонстрации достаточно одного. При отправке сообщения эту вкладку можно пропустить.

1. Подготовьте генератор на вкладке **«Ключи»** в том окне, которое используете. Откройте **«Простые числа»**.
2. В списке **«Длина числа в битах»** выберите `1024`. **«Случайное число»** создаёт число указанной длины. **«Простое число»** ищет число этой длины, которое прошло оба теста.
3. Чтобы проверить число вручную, замените содержимое поля **«Число для проверки (десятичное)»** на `65537` и нажмите **«Проверить обоими тестами»**. Оба теста сообщат «вероятно простое». Повторите с `45561`. Число составное, оно делится на 3.
4. Для поиска в интервале укажите `11` в поле **«От»**, `19` в поле **«до»** и нажмите **«Найти простые»**. Программа покажет `11, 13, 17, 19`. Обе границы входят в поиск.

## Как устроены алгоритмы

### Генератор чисел

Каждое окно записывает координаты и метку времени 96 событий движения. Из этих данных и имени стороны собственная реализация SHA-256 вычисляет начальный секрет. Генератор начинает счётчик с нуля. Каждый следующий блок равен `SHA256(секрет || счётчик)`, где счётчик занимает 16 байт, а `||` означает соединение байтов. Один блок даёт 256 бит. Для больших чисел генератор соединяет несколько блоков. Чтобы выбрать число из диапазона, он отбрасывает значения за его верхней границей. Это сохраняет равномерность выбора при равномерных исходных битах.

**Что делает SHA-256.** Функция дописывает к данным единичный бит, нули и исходную длину. Затем читает данные блоками по 512 бит. Каждый блок проходит 64 раунда битовых сдвигов, логических операций и сложений по модулю 2³². Восемь итоговых 32-битных слов образуют 256-битный хеш. На защите эту функцию можно проверить известным значением для строки `abc` в тесте `test_sha256_vectors`.

Одинаковое начальное состояние воспроизводит ту же последовательность в тестах. Непредсказуемость реального ключа зависит от начального состояния. Количество движений мыши само по себе не гарантирует 256 бит энтропии. Это учебный генератор для работы с искусственными сообщениями. Исходный код не вызывает `random`, `secrets`, системный генератор или `hashlib`.

### Проверка на простоту

Для GM программа строит два разных 1024-битных кандидата `p` и `q`. Две старшие единицы обеспечивают ровно 2048 бит у произведения. Две младшие единицы дают остаток 3 при делении на 4. После отсева кратных малым простым каждый оставшийся кандидат проходит два теста.

- **Миллер-Рабин.** Раскладываем `n − 1 = d · 2ˢ`, где `d` нечётно. Выбираем основание `a`, считаем `aᵈ mod n`. Если получили 1 или −1 по модулю n, раунд пройден. Иначе последовательно возводим результат в квадрат до `s − 1` раз. Если −1 так и не появился, число составное. Для принятия большого кандидата нужны 32 успешных раунда.
- **Соловей-Штрассен.** Для нового основания `a` сравниваем `a^((n−1)/2) mod n` с символом Якоби `(a/n)`, приведённым по модулю n. Символ Якоби программа вычисляет делением на двойку и перестановкой аргументов по закону квадратичной взаимности. Нулевой символ или несовпадение доказывает составность. Выполняются 16 раундов.

Фраза «вероятно простое» означает, что все выбранные основания прошли проверку. Свидетель составности позволяет сразу прекратить поиск для данного кандидата. Для модульного возведения в степень используется встроенная целочисленная операция Python `pow(a, e, n)`.

### Шифрование GM (Голдвассер-Микали)

В формулах `mod` означает остаток от деления. Например, `10 mod 7 = 3`.

Получатель публикует произведение `n = p · q` и хранит множители `p` и `q` в секрете. Из-за выбора простых вида `4k + 3` число −1 является квадратичным невычетом по каждому из них. Иными словами, никакой квадрат по модулю такого простого не даст −1.

1. Отправитель переводит текст в байты UTF-8. Для **каждого бита** выбирает новое число `r` от 1 до `n − 1`, взаимно простое с `n`.
2. Ноль кодируется числом `r² mod n`. Единица кодируется числом `−r² mod n`.
3. Получатель знает `p` и вычисляет `c^((p−1)/2) mod p`. По критерию Эйлера результат 1 означает квадрат (бит 0), результат `p − 1` означает невычет (бит 1). Из битов собирается исходный текст.

**Пример для доски.** Пусть `p = 7`, `q = 11`, тогда `n = 77`. Возьмём `r = 2` отдельно для иллюстрации каждой формулы. Ноль превратится в 4, а единица в 73. По модулю 7 это 4 и 3. Среди квадратов по модулю 7 встречаются только 0, 1, 2, 4. Получатель различает биты. В программе каждый бит получает своё случайное значение `r`.

При модуле 2048 бит один бит сообщения даёт 256 байт шифротекста. Например, `Привет!` занимает 13 байт UTF-8 и превращается в 26 624 байта. Ввод ограничен 128 байтами. В окне отображается начало шифротекста, а подписывается и передаётся весь пакет. [Работа Голдвассер и Микали](https://mit6875.github.io/PAPERS/probabilistic_encryption.pdf)

### Подпись HORS

Хеш можно представить как короткий отпечаток данных. Одинаковые данные дают одинаковый хеш. Если в тексте поменять даже один символ, хеш обычно изменится. По самому хешу исходный текст восстановить практически невозможно.

Закрытый ключ содержит таблицу из 4096 секретных 32-байтовых значений. Открытый ключ содержит SHA-256 каждого значения в том же порядке.

1. Отправитель вычисляет SHA-256 всего шифротекста. Первые 192 бита разбивает на 16 групп по 12 бит. Каждая группа задаёт номер строки от 0 до 4095.
2. Для подписи берутся 16 секретных значений из этих строк, всего 512 байт.
3. Получатель сам вычисляет номера по полученному шифротексту, хеширует каждое значение из подписи и сравнивает с соответствующей строкой открытого ключа. Все 16 сравнений должны совпасть.

Подпись раскрывает часть секретной таблицы. Сразу после подписания программа помечает ключ использованным и освобождает ссылку на закрытую таблицу. Проверять готовую подпись можно многократно. Если заменить блок шифротекста, изменятся хеш и выбранные строки. Подпись проверяется **до расшифровки**, поэтому подмена обнаруживается ещё до показа текста. [Исходное описание HORS, рисунок 1](https://cs-www.bu.edu/faculty/reyzin/papers/one-time-sigs.pdf)

### Обмен ключами

Кнопка передачи моделирует доверенный обмен открытыми ключами между двумя окнами одного процесса. При доставке получатель запоминает открытый ключ проверки для этого пакета. Кнопка подмены изменяет только полученную копию. Закрытые параметры можно посмотреть для защиты работы в собственном окне. В журнал и во второе окно они не передаются. Учебное приложение не предназначено для реальной конфиденциальной переписки.

## Что сказать на защите

> Получатель создаёт ключ шифрования из двух больших простых чисел и отдаёт отправителю их произведение. Отправитель шифрует текст этим открытым ключом и подписывает шифротекст своим ключом HORS. Получатель проверяет подпись открытым ключом отправителя и расшифровывает текст своим закрытым ключом. Если изменить шифротекст, получатель увидит ошибку проверки. ## Автоматические тесты

Из каталога `pract6`:

```sh
python3 -m unittest -v
python3 test_app.py --gui
```

Первая команда выполняет тесты без графического рабочего стола. Проверяются известные значения SHA-256, воспроизводимость генератора, оба теста простоты, числа Кармайкла, размеры ключей GM, шифрование UTF-8 и нулевого байта, проверка HORS с неверным ключом, блокировка повторного подписания и подмена полученного пакета. Отдельный сценарий вызывает обработчики двух окон с тестовыми виджетами.

Вторая команда открывает два настоящих окна Tk, воспроизводит сбор событий мыши, передаёт ключи и сообщение, проверяет расшифровку и обнаружение подмены, затем закрывает окна. Для Windows замените `python3` на `py`.
